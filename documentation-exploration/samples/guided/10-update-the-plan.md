# Update the plan

Next week’s plan is a working view. When a new request arrives or Bruce’s Friday changes, Diana returns to **Schedule**, selects the week, and checks time off and red days before deciding what to move. An Editor, Admin or Owner can update bookings and people; Bruce can review the schedule as a Viewer and ask Diana to make a correction.

For a recent mistaken change on **Schedule**, use **Undo** in the toolbar. Undo and redo history is held for the current page session. It clears on a reload, changing company context or another person’s change to the plan, and does not travel between devices. It is not a substitute for a saved schedule.

## If a save is uncertain

Server problems stay visible as error notices. Check the saved row before making the same change again. CapacityLens has no offline planning mode; unsaved changes are not a separate browser copy you can rely on.

If the response to a save was uncertain, the app reloads the latest server schedule so you can compare it with the change you meant to make. Review the row and reapply any change that is still missing. Do not assume that a request succeeded because the bar moved briefly while editing.

If an open allocation form reports that the schedule changed while you were editing, close the form and reopen the booking. Read the current values, then apply your change again. This avoids overwriting someone else’s newer work.

For the next planning pass, start at [Plan next week](01-plan-next-week.md), or open the page that matches the change: [record time off](05-add-time-off.md), [check capacity](06-find-capacity.md), or [book work](07-book-work.md).
