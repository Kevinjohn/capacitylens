# Set up the work

Diana is planning a Website refresh for Wayne Enterprises. The schedule groups work through a client, a project, and an activity, so she creates them in that order.

On **Clients**, Diana selects **Add client**, enters **Wayne Enterprises**, and saves. On **Projects**, she selects **Add project**, names it **Website refresh**, and chooses Wayne Enterprises as the client. The project now has the client relationship that makes it filterable with other Wayne Enterprises work.

Next, Diana opens **Activities**, selects **Add activity**, and enters **Design**. She sets **Kind** to **Project-specific** and chooses Website refresh. This activity belongs to that project. It will appear as a choice when Diana books Website refresh work.

## Keep activity scope clear

Choose **Project-specific** when the activity belongs to one project, as Design does here. **All projects** activities can be reused across projects; an allocation may optionally attribute one of those bookings to a project. **Internal** activities are for internal work and do not belong to a client project. These choices keep the booking’s project and activity consistent.

CapacityLens plans work by activity over days; it is not a task list or a timesheet. For this first pass, one broad activity named Design is enough. Add detail only when the team needs to distinguish different kinds of work in the schedule.

With the catalogue ready, Diana can note any absence before putting Bruce’s work on the week: [Record the absence](05-add-time-off.md). If Wayne Enterprises and Website refresh already exist, start at **Activities** and add only what is missing.
