CapacityLens: setup & first-run guide

Everything between "I found the repo" and "my team is planning in it" — which mode to run, what the first screens look like, and how to bring people in. Screenshots are small; click any of them for the full-size version.

Step 0

Pick your mode

One environment variable, SMALLSASS_ACCOUNT_MODE, decides which world you're in. Start with the demo; graduate to password auth when you want real logins.

Try it — 1 command

Demo

In-memory sample data, no login, resets on refresh. Perfect for "is this for us?".

Default

Open access

Real database, no logins. Anyone who can reach the URL can view and edit. Fine on a trusted network.

Recommended for teams

Password auth

Login wall, one Owner, roles, invite links. ~5 minutes of .env setup.

Companies with an IdP

SSO / OIDC

Same roles and invites; identity comes from your identity provider. See authentication.md.

Path A

Demo it in one command

# in-memory demo: sample data, no server persistence, no login
corepack enable
pnpm install
pnpm run dev:demo   # then open http://127.0.0.1:5173

You get a cosmetic company chooser ("Studio North" / "Loft Digital") and a fully editable schedule. Nothing persists — refresh and it resets. There are no credentials because there are no accounts.

No default admin password exists in production. The frictionless demo is credential-free by design. The dev-only CAPACITYLENS_CREATE_ADMIN_ADMIN=1 bootstrap (admin@admin.admin / admin) is refused by production builds.

Path B

Self-host with password auth — the five-minute install

Fill in four lines of .env, start the app, click through three screens. That's the whole journey.

  1. Fill in the .env

    Copy .env.example to .env and set:

    SMALLSASS_ACCOUNT_MODE=password
SMALLSASS_ACCOUNT_SECRET=<random 32+ chars>      # session signing
SMALLSASS_ACCOUNT_PUBLIC_URL=https://plan.example.com
SMALLSASS_ACCOUNT_SETUP_TOKEN=<random 32+ chars> # claims the Owner seat, used once

    Then start via Docker Compose or bare metal — see self-hosting.md.

  2. Claim the Owner account

    Visit the URL. With an empty database, the login wall becomes a "create the owner account" form: name, email, password, and your setup token. The moment it succeeds, self-registration closes — nobody else can sign themselves up. On every later visit this is the plain sign-in screen:

  3. Create your first company

    You land on an empty company picker. Creating a company also creates its built-in "Internal" client and your Owner membership, all in one step.

  4. A 20-second orientation

    Once per device you get a short welcome that sets expectations: this is a resourcing tool, not project management.

  5. You're up and running

    The Schedule opens with a Getting Started panel offering two tracks: build the schedule (clients → projects → resources → allocations) and give people access (optional). No sample data is seeded in a real install — what you add is yours.

Bringing people in

Invites: a link you hand over yourself

CapacityLens sends no email. You create a single-use link and deliver it however you already talk to your team — Slack, DM, carrier pigeon. This is a deliberate choice: no SMTP setup, no deliverability headaches.

  1. Open Team & access, pick a role

    Owners and Admins see an "Invite someone" panel. Choose the role (its consequences are spelled out underneath) and optionally pre-authorise an email address.

  2. Copy the one-time link

    The link is shown once — only its hash is stored — so copy it now and send it to the person.

  3. They preview before joining

    The invite page shows the company, the proposed role, what that role can and can't do, and the expiry. Previewing changes nothing. Existing users sign in and accept; new people create their account and accept in one atomic step, landing straight in the company.

Who sees what

Roles at a glance

Four strictly nested roles — Viewer < Editor < Admin < Owner — with exactly one Owner per company. Everyone sees the same navigation; roles change what's editable and visible inside each page, enforced server-side.

A note on the model: app members and scheduled resources are separate. Joining a company doesn't put you on the schedule, and being on the schedule doesn't give you a login. Most teams have a few members and many resources.
