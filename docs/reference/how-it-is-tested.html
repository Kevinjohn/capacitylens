How CapacityLens is tested ​

Contributor check commands are listed in CONTRIBUTING.md.

The suites cover the frontend, backend and shared workspace packages.

SuiteToolCovers
App and shared unit testsVitest, Testing LibraryShared scheduling rules, the client store and React components
Backend testsVitestAPI behavior, authorization, SQLite, backups and sign-in
End-to-end testsPlaywrightThe demo and database-backed sign-in and scheduling flows in a real browser
Accessibility checksaxe, inside the end-to-end testsAutomated accessibility rules on key screens
Mutation testingStrykerWhether focused tests detect changes to scheduling logic; run on demand

Limits of each suite ​

  • Backup and upgrade tests cover supported databases and recovery behavior.
  • End-to-end tests run Chromium by default. WebKit and Firefox runs are opt-in.
  • Axe finds common problems such as missing names and low contrast. It does not replace testing with assistive technology.
  • Mutation testing covers only the pure scheduling and helper code, not the server or React screens.

The repository README shows CI status, code coverage, CodeQL, OpenSSF Scorecard and OpenSSF Baseline badges. The OpenSSF Baseline assessment has the evidence behind the Baseline badge.
