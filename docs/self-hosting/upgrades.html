Upgrade CapacityLens ​

Keep the database and backup directory outside versioned release folders. Before changing the running code, read the release notes and confirm that a recent snapshot can be read. Use one process and stop it before replacing files or running the migration command.

Install the new release ​

Download the archive for the host's operating system and architecture. Verify its checksum, unpack it next to the current release, and move the current link to the new version. Do not overwrite an existing release folder.

Upgrade the database ​

From the new release's backend/ directory, with the same environment used by the service, run:

bash
node ace.js app:upgrade

For an existing database, this command writes and verifies an online pre-upgrade snapshot before running migration:run --force --no-schema-generate. A fresh database is initialized without a pre-upgrade snapshot. Schema drift refuses the upgrade. Do not start the new service after a failed upgrade; retain the source database and recovery files and investigate the reported refusal.

After a successful upgrade, start the service and check /health/ready. Keep the snapshot until the new release has passed sign-in, reads, writes and backup checks. Pre-upgrade snapshots are kept separately from daily/manual retention; copy them off-host and keep the needed recovery points.

Roll back ​

Migrations are forward-only; there are no down migrations. To roll back an application release, stop the service and restore the verified pre-upgrade snapshot to a separate database path, then point CAPACITYLENS_DB at that restored copy before starting the earlier release. Preserve the upgraded database and all recovery files until the rollback is confirmed.

See Backups and restore for snapshot handling and Monitoring for readiness checks.
