CapacityLens threat model ​

Baseline version: 2026-09-23. Authentication posture reviewed: 2026-10-26, after the Account Kit cutover in #1582. This update reconciles current controls; it is not a fresh review of the full model. Review the model after changes to authentication, tenancy, imports, browser storage, deployment topology or external services.

Security objectives ​

  1. A user can read or change only accounts, operations, records and protected fields allowed by their current server-side membership and role.
  2. Passwords, session tokens and emailed bearer links are not disclosed or stored in recoverable form where a safer representation is available.
  3. Tenant writes remain valid, atomic and attributable; schema drift prevents startup.
  4. Browser-delivered code cannot silently turn an authenticated browser into a cross-site write primitive, and sensitive API responses are not cached.
  5. Operators can contain a compromised identity, restore authoritative data and investigate the application audit record without relying on the compromised host alone.

CapacityLens is not a safety-critical, payments, classified-data, real-time media or anonymous public-upload system. Availability is important, but confidentiality and tenant integrity take priority over keeping a misconfigured production process running.

The browser talks to the application over the configured public origin. Operators terminate public TLS and protect the host, database and snapshots. SMTP is the only default outbound application service; its configured connection requires TLS and certificate verification. Emailed action links place bearer values in URL paths, so access logs at the proxy or mail service must not record them.

Actors ​

  • A Viewer, Editor, Admin or Owner acting maliciously within their legitimate account.
  • An authenticated user attempting cross-company or higher-role access.
  • An unauthenticated internet attacker, credential-guessing bot or cross-site origin.
  • A person with access to a mailbox, forwarded invitation or compromised browser/device.
  • A malicious or compromised dependency, build input or release credential.
  • A self-hosting operator who makes an unsafe configuration choice or misuses operator access.
  • A host-level attacker. In-process controls cannot fully contain host compromise; isolation, secret management and off-host backups/logs limit consequences.

Residual and accepted risks ​

  • Authentication is password-only. There is no local MFA, identity-provider sign-in, breached-password screening, member session inventory or administrator session-revocation screen.
  • Sessions use a 14-day sliding idle expiry, have no absolute lifetime, and have no configured maximum number of simultaneous sessions. Password changes and resets revoke sessions, but operators cannot revoke another member's active sessions through the product.
  • Account Kit's operator commands are registered alongside the product's stricter owner-recovery path. The host operator already has database authority; some Kit commands do not create product audit rows. Treat command access as privileged host access and retain shell audit evidence.
  • Sign-in outcomes are not product audit rows. The opt-in application log records password sign-in success, credential failure and throttling separately from the request completion event.
  • Password reset and invitation bearers occur in URL paths. Application route logging suppresses sensitive path values, but proxy, SMTP and mailbox access remain operator-controlled boundaries.
  • SMTP delivery, mailbox security and retention, public TLS, encrypted host volumes, secret-manager use, clock synchronization, log retention and off-host collection require deployment evidence.
  • The single-process SQLite service can still be denied service by sufficient network or tenant-valid load. Edge rate limiting, connection limits and resource monitoring remain operator controls.
  • Host compromise is outside the containment boundary of application code. Protect the database, APP_KEY, mail credentials, backups and operator shell access accordingly.
