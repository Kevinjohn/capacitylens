Security control inventories ​

Version: 2026-10-26. These inventories support ASVS architecture requirements; they are not a substitute for deployment-specific data classification, key inventory or log-retention policy.

Entry points and untrusted input ​

InputFormat and limitTrusted enforcementSecurity treatment
Tenant API route, body, query and pathAdonis BodyParser defaults; compiled Vine schemasAdonis and shared domainAuthenticated operation; server membership/action checks, validated fields and relational checks; unknown Vine object properties are stripped
Whole-company importJSON; framework request-size defaultOwner-only API and SQLiteSchema validation, reference checks, import preparation and atomic replacement
Password creation, change and reset15–128 Unicode code pointsAccount Kit with application auth routesPassword length validation; no common-password or breached-password screening
Sign-in credentialsEmail and password in bounded JSONAccount Kit with application auth routesGeneric invalid-credential response and authentication throttling
Registration, invitation, address-confirmation and reset linksBounded JSON/path/header values; invitation 7 days, other emailed links 1 hourAccount Kit plus application routes and admission policyOne-time links are stored as SHA-256 digests; address confirmation and admission are checked before product access
Action-proof requestPassword plus bounded action/intent payloadApplication route and action_proof.tsOwner authority is checked in the current Kit transaction; the five-minute proof binds user, session, company, action and intent and is consumed with the mutation
Operator commandsShell arguments and current SQLite stateRegistered Account Kit/operator commands (excluding account-kit:reset-link)Bootstrap issues the first invitation; owner:reset-password requires a stopped server and eligible sole Owner and writes an audit row before displaying its link
CORS, origin and forwarding headersHTTP headersRoot middleware and configured proxy trustExact origin policy, unsafe cross-site rejection and configured trusted-proxy handling
Environment and numeric settingsProcess environmentStartup parsers and configuration providerBounded integers, explicit boolean grammar and production guards

There is no runtime XML, LDAP, XPath, GraphQL, WebSocket, WYSIWYG, LaTeX, archive, image, arbitrary file-upload, CSV/spreadsheet, template, shell-command, JNDI, memcache, WebRTC or media processing entry point.

Sensitive data and retention ​

ClassExamplesStorage/transportRetention and disclosure
Authentication secretsPassword verifier, session id, reset/invitation/action-link tokensSQLite and session cookie; emailed links through configured SMTPSession registry expires after 14 days without use; link lifetimes are defined above; raw credentials and bearer values are not written to application logs
Identity and admission dataName, email, memberships, invitation evidence, approval decisions and last sign-in confirmationSQLite over the configured connectionRetained while needed for account access; identity/account removal follows the account deletion policy
Tenant confidential dataSchedule, notes and real private client/project namesSQLite, backups and role-filtered APIOperator controls database, exports, backups and retention
Audit metadataTimestamp, actor, company, action, entity, id and changed field namesTransactional audit_entries rows in SQLiteValues and credentials are not included; database and backup retention are operator-controlled
Session metadataUser, session registry handle, user-agent label (up to 200 characters), expiry and last-seen timeKit session registry and application session store in SQLite14-day idle expiry; no absolute lifetime or concurrent-session cap; no product session inventory or administrator revocation screen
Device preferenceTheme, zoom and similar settingsBrowser localStorageDevice-local and outside company export

Every /api/* response receives Cache-Control: no-store and Pragma: no-cache. The SPA contains no advertising, analytics or crash-reporting integration. SMTP is the only default outbound application service. Its configured connection requires TLS and certificate verification, with 5-second connection and greeting timeouts and a 10-second socket timeout. Authentication mail contains a one-time bearer link; operators should prevent proxy, SMTP and mailbox logs from retaining its URL path.

Runtime node:crypto importers are accounted for here: apps/backend/app/models/user.ts creates UUID identifiers; account_commands.ts creates command UUIDs and payload hashes; auth/action_proof.ts creates proof UUIDs and intent hashes; auth/request_limit.ts hashes client IP keys; beta_account_transfer.ts hashes import snapshots; and planning_operations/restoration.ts creates restoration-group UUIDs. The browser uses Web Crypto for UUIDs and a command digest. Build scripts use SHA-256 for file integrity; packaged-server smoke tooling uses UUIDs. These are identifiers or integrity/limiter hashes, not password or bearer-token storage.

The cryptographic inventory is reviewed by hand; no gate discovers implementation paths. Review it after cryptographic changes. APP_KEY configures the application AES-256-GCM encryptor and Account Kit limiter secret; current application call sites for encrypted stored data are not established. CAPACITYLENS_SECRET is checked for length at boot when authentication is enabled, but does not derive application keys. Operators maintain their deployment key/certificate inventory, rotation policy and backup-encryption controls.

Production configuration requires application audit to remain enabled. Authentication outcomes use the opt-in application log stream, not transactional audit rows. The operator must document access, retention, time synchronization, alerting and any external log collection.

Third parties and build inputs ​

  • Runtime includes Node.js 24, AdonisJS, Account Kit (vendored archive), React/UI packages, SQLite in Node and configured SMTP. Account Kit is pinned by lockfile integrity and is outside Dependabot's direct package release tracking.
  • Build/test inputs include pnpm registry packages, GitHub Actions, CodeQL, Playwright browsers, Vitest, ESLint, Stryker, Gitleaks, Syft/Anchore, Trivy and OWASP ZAP.
  • pnpm-lock.yaml pins the dependency graph. Reviewed overrides keep vulnerable transitive packages on compatible patched releases where needed. GitHub actions are full-commit pinned; Dependabot covers npm and Actions.
  • pnpm lifecycle-script policy is fail closed; allowBuilds permits only reviewed install scripts.
  • CI performs dependency review, production audit, secret scanning, CodeQL, SBOM generation, vulnerability scanning, DAST and release provenance. Published releases attach the packaged build, SPDX SBOM and GitHub-issued provenance bundle as release assets. The blocking DAST baseline scans the only supported posture, password sign-in, as the deployment guide configures it. The public-repository workflows run automatically on their documented events and remain manually runnable for deliberate reruns.
