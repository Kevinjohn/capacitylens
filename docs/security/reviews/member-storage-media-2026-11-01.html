Member storage and media verification — 2026-11-01 ​

This follow-up completes the verification work in #1711, following #1700 and PR #1702. The application and original media inputs are pinned to c7e3aaa5c88cd7fea7bca10d8ae1148a7cbe74de; this follow-up adds tests, evidence and walkthrough context. It changes no production directory, authentication or database behavior. Final test commands, results and the delivery revision are recorded in the PR.

Malformed member storage ​

The real SQLite regression suite covers invalid membership role, invalid membership status and invalid restriction-only role. A valid Owner reads another principal, so a failed authorization cannot substitute for the intended guard. Each case checks its exact service error and an actual authenticated directory GET: generic 500 { error: 'Internal server error.' }, without a partial successful directory, raw corrupt value or stack under the existing debug-off policy. Healthy and restored reads return 200. Three separate guard-bypass probes fail at their matching assertions.

The restriction table has a role CHECK. Its fixture inserts a valid row, proves invalid SQL writes are refused, closes the sole idle physical SQLite handle, and replaces one uniquely identified same-length row value in the disposable test file. The retained logical pool opens a fresh handle. The table schema remains identical, CHECK enforcement remains enabled, and invalid updates are still refused afterward. No constraint or foreign key is disabled and no second writer is added. This is a test-only corruption fixture, not a repair capability.

Snapshots cover membership, restrictions, settings, planning revision, audit and command receipts: directory reads neither repair the malformed row nor write those product states. Normal session bookkeeping is outside that assertion. Foreign-company malformed membership role/status and restriction-only role do not poison the authorized directory. A membership-backed principal's overlapping restriction is skipped when projecting restriction-only entries, preserving the existing membership role and disabled-access flag. Existing compile-time negative cases remain.

Focused runtime results and three guard-bypass failures pin the test source and unchanged production service hashes.
