# Glossary

Each term links to the page that covers it in depth.

| Term | Meaning |
| ---- | ------- |
| <span id="account">account</span> | In the app, **Account** is the personal page for your sign-in, password and sessions. Exports and technical records call a company an account; screens and these docs say **company**. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="activity">activity</span> | The work placed on the schedule. It can belong to one project, be internal work with no project under the built-in **Internal** client, or be reusable across all projects. See [Schedule and change work](/using/schedule-work). |
| <span id="admin">Admin</span> | The role below Owner. An Admin can invite and manage members, see time-off notes and restore archived records, but cannot act on the Owner. The Owner transfers ownership to an eligible Admin immediately; the Admin does not separately accept. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="all-projects">All projects</span> | An activity that can be booked against any active project, such as account management. Each booking may count towards one chosen active project whose client is also active; **No specific project** leaves it unattributed. See [Schedule and change work](/using/schedule-work). |
| <span id="allocation-units">allocation units</span> | The company setting for how bookings are entered: **Hours** per day across dates, **Days** of work spread over a span (the default), or **Blocks**, a start and days over with no hours, so utilisation is ignored. See [Choose company settings](/admin/company-settings). |
| <span id="booking"></span><span id="allocation">booking</span> | A person booked to an activity for a date range, shown as a bar in their row with a tentative, confirmed or completed status. The form calls it an allocation, as in **New allocation** and **Allocation units**. See [Schedule and change work](/using/schedule-work). |
| <span id="capacity">capacity</span> | The time a person has available to book: their working days, together with the company's, inside their availability dates. Outside those dates, and during time off and company closures, it is zero. See [Ongoing administration](/admin/ongoing-administration#change-working-patterns). |
| <span id="client">client</span> | Groups the projects your company does for one customer. Internal work goes under the built-in **Internal** client. See [Schedule and change work](/using/schedule-work). |
| <span id="company">company</span> | The workspace with its own clients, projects, activities, people and schedule. A server-backed installation serves one company; the temporary demo includes two fictional companies. Company-scoped authorization remains enforced by the server. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="company-closure">company closure</span> | Time off for the whole company, added under **Time off → Company closures**. It sets capacity to zero for every person and placeholder on those dates, including people added later, but not for external parties. See [Ongoing administration](/admin/ongoing-administration#add-a-company-closure). |
| <span id="demo-mode">demo mode</span> | The in-memory version with a fictional two-company dataset that resets on every reload and has no logins or roles. See [Try the demo](/getting-started/try-the-demo). |
| <span id="discipline">discipline</span> | A category people are grouped by, such as Design or Development, used for filtering and per-discipline utilisation. New production companies start with Use disciplines off; an Editor or above can turn it on in Settings. See [Settings](/using/settings). |
| <span id="editor">Editor</span> | The role that books work: it can change the schedule, people, clients, projects, time off and most company settings, but cannot invite people. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="example-data">example data</span> | Fictional people, a client, a project and sample bookings added with **Add example data** in [Settings](/using/settings#example-data) while the company is still empty. They are ordinary records that can be archived. |
| <span id="external-party">external party</span> | A bookable resource such as a print shop or subcontractor that does not count towards utilisation. Off by default. See [Settings](/using/settings). |
| <span id="getting-started">Getting started</span> | The checklist on Schedule that ticks off five setup steps. It stays until an Owner or Admin dismisses it for everyone. Viewers don't see it. See [Quick start](/getting-started/quick-start#make-your-first-schedule-useful). |
| <span id="internal">Internal</span> | A kind of projectless activity for non-billable work, grouped under the built-in **Internal** client. The Project field's **Internal** choice is a UI label; there is no built-in Internal project. Internal work always appears in neutral grey. See [Prepare clients and work](/admin/prepare-work). |
| <span id="invite"></span><span id="invitation">invitation</span> | An emailed, single-use link an Owner or Admin sends to one address for a role. It lasts seven days, and **Resend** replaces the link. Accepting it still waits for an Owner or Admin to approve. See [Invite teammates](/admin/invite-teammates). |
| <span id="link-to-resource">Link to Resource</span> | The control in **Team & access** that joins a member to their person on the schedule. Each member and each person can have only one link, and linking does not change permissions. See [Add people to the schedule](/admin/add-people#connect-their-sign-in). |
| <span id="member">member</span> | Someone who can sign in to a company, as Owner, Admin, Editor or Viewer. Being a member does not put you on the schedule, and a scheduled person need not be a member. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="mfa-totp">MFA / TOTP</span> | MFA is a second proof of identity beyond a password; TOTP is a six-digit authenticator-app code. CapacityLens offers neither. See [Security and privacy](/security/). |
| <span id="over-capacity">over capacity</span> | Booked for more than the time available on a day, shown in red. Fully booked is not over capacity. A separate warning always looks 14 days ahead, whatever the zoom. See [Philosophy](/reference/philosophy). |
| <span id="overview">Overview</span> | The page showing each person's free days, week by week. Only Owners and Admins can open it unless the company opens it to Editors or everyone. Companies that schedule in Blocks cannot use it. See [Overview](/using/overview). |
| <span id="owner">Owner</span> | The one person per company with full control: the only role that can replace its whole dataset, anonymise all its people or transfer ownership to an active, unrestricted Admin. No Admin can reset an Owner's password or remove them. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="ownership-transfer">ownership transfer</span> | The Owner confirms a transfer to an active, unrestricted Admin. The selected Admin becomes Owner and the former Owner becomes Admin immediately; there is no nominee consent or pending transfer. See [Roles and permissions](/getting-started/roles-and-permissions#hand-the-company-to-someone-else). |
| <span id="person">person</span> | A schedule row that can receive bookings and time off. A person needs no sign-in, so you can schedule a freelancer without inviting them. See [Resources](/using/resources). |
| <span id="placeholder">placeholder</span> | An unfilled slot for a role not yet hired or assigned, so you can plan work without naming a person. See [Resources](/using/resources). |
| <span id="project">project</span> | Groups the activities and bookings for one piece of client work. Every project belongs to a client. See [Schedule and change work](/using/schedule-work). |
| <span id="red">red</span> | A warning colour with a different meaning in each place. On Schedule, a red day is [over capacity](#over-capacity) or work overlapping time off or a closure, and a red utilisation percentage means over capacity within the next 14 days. On Overview, a red bar means less than 40% of the week is free, a red figure counts overbooked days, and a red weekly total means confirmed and tentative work reach 90% of the week. A red **Clear Filters** means a filter is on. See [Spot overwork](/using/read-the-schedule#reading-overwork). |
| <span id="resource">resource</span> | Anything bookable: a person, placeholder or external party. Adding a resource creates no sign-in, and inviting a member adds no resource. See [Resources](/using/resources). |
| <span id="role">role</span> | What a member may do in the installation's company: Viewer, Editor, Admin or Owner, each able to do everything the one below can. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="schedule">schedule</span> | The week-by-week grid of every person's bookings and time off, zoomable from one to eight weeks. See [Schedule](/using/read-the-schedule). |
| <span id="session">session</span> | The time between signing in and signing out or timing out, tracked on the server. It ends after fourteen days without use, and changing your password ends every session. See [Security and privacy](/security/). |
| <span id="setup-token"></span><span id="setup-link">setup link</span> | The one-time link the installer prints with `account-kit:admission:bootstrap` for the first Owner. Opening it creates that person's sign-in; they then create the company. See [Access your company](/owner/create-your-company). |
| <span id="company-login"></span><span id="sign-in">sign-in</span> | Everyone signs in with an email address and password. There is no Google, Microsoft or other company sign-in. See [Sign-in and access](/company-login/). |
| <span id="sqlite-the-database">SQLite / the database</span> | The single file that holds everything: every company, person, booking and audit entry. Keep it and its backups on persistent storage. See [Backups and restore](/self-hosting/backups-and-restore). |
| <span id="tentative">tentative</span> | A booking status for work that is not yet confirmed, shown as a striped bar with a dashed border. It still counts towards utilisation and over capacity on Schedule, even while the **Tentative** pill hides it. The other statuses are confirmed and completed. See [Schedule and change work](/using/schedule-work). |
| <span id="time-off">time off</span> | A block marking a person unavailable, such as holiday, sick leave or unpaid leave. Company-wide closures are recorded separately; see [company closure](#company-closure). See [Time off](/using/time-off). |
| <span id="user">user</span> | A sign-in identity for the installation. A production installation serves one company, and being a user does not put anyone on the schedule. The two-company demo uses fictional identities without sign-in. See [Invite teammates](/admin/invite-teammates). |
| <span id="utilisation">utilisation</span> | How much of a person's available time is booked, as a percentage. Total, per-discipline and personal figures are available, and some modes let work be booked without counting towards it. See [Settings](/using/settings). |
| <span id="viewer">Viewer</span> | The role that can see the schedule and everyone's work but change nothing. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="working-days">working days</span> | The days of the week someone works. The company sets a shared working week and each person has their own; ordinary bookings use only working days. See [Add people to the schedule](/admin/add-people). |
