# Glossary

Each term links to the page that covers it in depth.

| Term | Meaning |
| ---- | ------- |
| <span id="account">account</span> | In the app, **Account** is the personal page for your sign-in, password and sessions. Exports and technical records call a company an account; screens and these docs say **company**. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="activity">activity</span> | The work placed on the schedule. It can belong to one project, be internal work with no project, or be reusable across all projects. See [Schedule and change work](/using/schedule-work). |
| <span id="admin">admin</span> | The role below Owner. An Admin can invite and manage members, see time-off notes and restore or purge archived data, but cannot act on the Owner; only a nominated Admin can agree to become the next Owner. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="allocation">allocation</span> | A person booked to an activity for a date range, shown as a bar in their row with a tentative, confirmed or completed status. See [Schedule and change work](/using/schedule-work). |
| <span id="all-projects">All projects</span> | An activity that can be booked against any active project, such as account management. Each booking may count towards one chosen active project whose client is also active; **No specific project** leaves it unattributed. See [Schedule and change work](/using/schedule-work). |
| <span id="break-glass">break-glass</span> | The operator's recovery when company sign-in is unavailable: restore password-capable mode and restart so local-password accounts can sign in. It does not reset passwords or change provider connections. See [Require company sign-in](/company-login/move-to-single-sign-on#restore-password-sign-in). |
| <span id="claims">claims</span> | What an identity provider reports about a person at sign-in: their email, whether it is verified, and a stable ID. CapacityLens uses them to admit someone and keep their sign-in linked to the same person. See [Set up Google or Microsoft sign-in](/company-login/set-up-company-login). |
| <span id="client">client</span> | Groups the projects your company does for one customer. Internal work needs no client. See [Schedule and change work](/using/schedule-work). |
| <span id="client-secret">client secret</span> | The private string an identity provider issues with a client ID, proving sign-in requests come from your server. It is usually shown once; protect it like a root password. See [Set up Google or Microsoft sign-in](/company-login/set-up-company-login). |
| <span id="company-login">company login</span> | Signing in through Google Workspace or Microsoft Entra ID instead of a CapacityLens password. See [How sign-in works](/company-login/). |
| <span id="company">company</span> | A separate workspace with its own clients, projects, activities, people and schedule. One installation can host several when multi-company is enabled; access and data never carry across. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="demo-mode">demo mode</span> | The in-memory version with a fictional two-company dataset that resets on every reload and has no logins or roles. See [Try the demo](/getting-started/try-the-demo). |
| <span id="discipline">discipline</span> | A category people are grouped by, such as Design or Development, used for filtering and per-discipline utilisation. On by default. See [Settings](/using/settings). |
| <span id="external-party">external party</span> | A bookable resource such as a print shop or subcontractor that does not count toward utilisation. Off by default. See [Settings](/using/settings). |
| <span id="identity-provider">identity provider</span> | The service that checks a person's sign-in and tells CapacityLens who they are. Google Workspace and Microsoft Entra ID are the supported providers. See [How sign-in works](/company-login/). |
| <span id="invite">invite</span> | A single-use link an Owner or Admin creates for a role and, optionally, an email address. With SMTP configured, addressed invitations are emailed; the creator can always copy the link. See [Invite teammates and manage access](/admin/invite-teammates). |
| <span id="link-accounts">link (accounts)</span> | Explicitly connecting your existing CapacityLens account to a Google or Microsoft identity while signed in. It keeps your membership, role and scheduled work. See [Connect an existing account](/company-login/#connect-an-existing-account). |
| <span id="member">member</span> | Someone who can sign in to a company, as Owner, Admin, Editor or Viewer. Being a member does not put you on the schedule, and a scheduled person need not be a member. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="mfa-totp">MFA / TOTP</span> | MFA is a second proof of identity beyond a password; TOTP is a six-digit authenticator-app code. CapacityLens has neither locally: set MFA at Google or Microsoft, and note a provider session does not prove MFA happened. See [Security overview](/security/) and [company login](/company-login/#multi-factor-sign-in-at-your-provider). |
| <span id="mixed-mode">mixed mode</span> | Password sign-in and company login both switched on. It is a supported permanent setup, not only a migration stage. See [Require company sign-in](/company-login/move-to-single-sign-on). |
| <span id="owner">owner</span> | The one person per company with full control: the only role that can delete the company, replace its whole dataset or start an [ownership transfer](#ownership-transfer). No Admin can reset an Owner's password or remove them. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="ownership-transfer">ownership transfer</span> | The Owner nominates an Admin, that Admin agrees and the same Owner confirms. Nothing changes until all three happen; either side can stop it, and a request expires after seven days. See [Roles and permissions](/getting-started/roles-and-permissions#hand-the-company-to-someone-else). |
| <span id="password-mode">password-capable mode</span> | Signing in with an email and password stored by CapacityLens rather than through a provider. The default for a new self-hosted install. See [Configuration](/self-hosting/configuration). |
| <span id="person">person</span> | A schedule row that can receive allocations and time off. A person needs no sign-in, so you can schedule a freelancer without inviting them. See [Resources](/using/resources). |
| <span id="pkce">PKCE</span> | A check in the sign-in handshake that stops a stolen sign-in code being reused. CapacityLens requires it from every identity provider. See [Set up Google or Microsoft sign-in](/company-login/set-up-company-login). |
| <span id="placeholder">placeholder</span> | An unfilled slot for a role not yet hired or assigned, so you can plan work without naming a person. See [Resources](/using/resources). |
| <span id="project">project</span> | Groups the activities and allocations for one piece of client work. Every project belongs to a client. See [Schedule and change work](/using/schedule-work). |
| <span id="redirect-uri">redirect URI</span> | Also called a callback URL: the address your identity provider returns people to after sign-in. It must match your CapacityLens address exactly, or sign-in fails. See [Set up Google or Microsoft sign-in](/company-login/set-up-company-login). |
| <span id="resource">resource</span> | Anything bookable: a person, placeholder or external party. Adding a resource creates no sign-in, and inviting a member adds no resource. See [Resources](/using/resources). |
| <span id="role">role</span> | What a member may do in a company: Viewer, Editor, Admin or Owner, each able to do everything the one below can. Roles are per company, so one person can be an Editor in one and a Viewer in another. See [Roles and permissions](/getting-started/roles-and-permissions). |
| <span id="schedule">schedule</span> | The week-by-week grid of every person's allocations and time off, zoomable from one to eight weeks. See [Schedule](/using/read-the-schedule). |
| <span id="session">session</span> | The time between signing in and signing out or timing out, tracked on the server. It lasts at most twelve hours and ends after thirty minutes of inactivity. See [Security overview](/security/). |
| <span id="single-sign-on-sso">single sign-on (SSO)</span> | Signing in with the account you use for your company's other tools. These docs call it company login. See [How sign-in works](/company-login/). |
| <span id="snapshot-offline">snapshot (offline)</span> | The read-only copy of a company's schedule kept on your device when offline access is on. It expires after seven days and never accepts edits. See [Offline access](/using/settings#offline-access). |
| <span id="social-sign-in"></span><span id="provider-sign-in">provider sign-in</span> | Signing in through Google, Microsoft or, in mixed mode only, experimental GitHub, which cannot satisfy provider-required sign-in. A new identity still needs a verified email and an invitation or bootstrap allowance. See [How sign-in works](/company-login/). |
| <span id="sqlite-the-database">SQLite / the database</span> | The single file that holds everything: every company, person, allocation and audit entry. Keep it and its backups on persistent storage. See [Backups and restore](/self-hosting/backups-and-restore). |
| <span id="time-off">time off</span> | A block marking a person unavailable, such as holiday, sick leave or unpaid leave. An Everyone entry records a company-wide closure for every tracked person. See [Time off](/using/time-off). |
| <span id="user">user</span> | A sign-in identity for the whole installation, not one company. One user can be a member of several companies with different roles, and being a user does not put anyone on the schedule. See [Invite teammates and manage access](/admin/invite-teammates). |
| <span id="utilisation">utilisation</span> | How much of a person's available time is booked, as a percentage. Total, per-discipline and personal figures are available, and some modes let work be booked without counting toward it. See [Settings](/using/settings). |
